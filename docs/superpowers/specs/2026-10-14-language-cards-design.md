# Telegram Mini App для совместного изучения слов

Дата: 14 октября 2026 года.

Статус: утверждена пользователем 14 октября 2026 года с уточнениями о выбранном стеке, единственном авторе новых общих карточек и минимальном содержимом учебной карточки. Документ описывает согласованный дизайн, а не выполненную реализацию.

## 1. Согласованные требования

### Цель

Компания друзей добавляет свой список слов и фраз, открывает приложение в Telegram и повторяет карточки по принципу Anki. Забытое возвращается чаще; хорошо запомнившееся — реже. Пользователь сам решает, когда начать и закончить занятие.

| ID | Требование |

| R02 | Разработка следует Spec-Driven Development: требования и критерии приёмки → спецификация → план → реализация и проверка. |

Автор редактирует свои общие карточки, пока состоит в группе; создатель группы может редактировать и удалять любые общие карточки. Создатель не получает право добавления автоматически. ### Границы первой версии

Первая версия покрывает текстовые карточки, импорт списка, группы, личные карточки и интервальные повторения. Интерфейс — на русском, исходный сценарий — английский и русский. Текст карточек сохраняется как Unicode без автоматической проверки языка или исправления переводов.

Импорт файлов Anki, синхронизация с Anki, изображения, аудио, генерация переводов, рейтинги участников, оплата и офлайн-синхронизация в этот объём не входят. Сходство с Anki относится к механике обучения; совместимость его файлов и точное совпадение интервалов не заявляются.

## 2. Подход к реализации

Варианты ниже были рассмотрены при проектировании. Пользователь выбрал первый вариант.

| Вариант | Что даёт | Цена решения |
| --- | --- | --- |
| Python/FastAPI + React/TypeScript | Отдельный интерфейс для карточек, предпросмотра импорта и состояний сохранения; явный контракт API | Нужно поддерживать Python и небольшой фронтенд на TypeScript |
| Python/Django + серверные шаблоны и JavaScript | Основная разработка остаётся в Python; формы и страницы можно собирать на сервере | Динамическое состояние тренировки и редактирование списка потребуют отдельной клиентской логики |
| Python/FastAPI + HTML/CSS и обычный TypeScript | Небольшой набор инструментов для компактного интерфейса | Состояния экранов, компонентов и навигацию придётся организовать вручную |

Выбран первый вариант, один серверный сервис и одна база PostgreSQL. React отвечает за отображение и взаимодействия, Python — за доступ к данным, импорт и расписание повторений. API описывается через OpenAPI; FastAPI предоставляет соответствующие механизмы в своей [официальной документации](https://fastapi.tiangolo.com/).

Telegram Mini App использует веб-интерфейс; Python остаётся основным языком серверной части. Возможности запуска и интеграции описаны в [документации Telegram Mini Apps](https://core.telegram.org/bots/webapps).

Этот стек утверждён и используется в плане реализации.

## 3. Карточки, группы и владение данными

### Общая карточка

Пользовательское содержимое — две текстовые стороны, например `Receive` и `получать/принимать`. Для изучения из них получаются два задания; текст хранится один раз. Автор, группа и версия содержимого остаются служебными данными сервера и не отображаются на учебной карточке.

Создание и импорт общих карточек разрешены только аккаунту, чей подтверждённый Telegram ID совпадает с серверной константой `SHARED_CARD_PUBLISHER_TELEGRAM_ID = 1568151709`. Один ID применяется ко всему приложению; даже этот аккаунт работает только с группами, в которых состоит. Проверка обязательна для одиночного создания, пакетного импорта и любых операций, которые могли бы создавать общие карточки. Права задаются на сервере; скрытие кнопки в интерфейсе само по себе не является проверкой доступа.

Пользователь сообщил этот ID явно. Проверка не использует имя или username, а значение не изменяется через интерфейс либо переменную окружения. Самоназначения издателя первым вошедшим пользователем нет. Отсутствующая или некорректная константа не даёт никому право добавления общих карточек.

Общая карточка принадлежит группе. Когда автор выходит из группы, карточка остаётся доступной её участникам. Автор может редактировать свою общую карточку только пока состоит в группе.

### Личная карточка

Личные карточки принадлежат пользователю независимо от группы. В тренировку выбранной группы включаются её общие карточки и личный набор пользователя. При смене группы личный прогресс сохраняется; при выходе из группы личные карточки остаются.

Создатель группы не получает доступа к чужим личным карточкам или истории повторений. Пользователь редактирует и удаляет собственные личные карточки.

### Группы

Пользователь может состоять в нескольких учебных группах. На главном экране выбирается одна активная группа; приложение запоминает последний выбор. Также доступен режим «Личные карточки» без общей группы.

Создание требует только названия группы. Создатель получает ссылку-приглашение. При переходе человек видит название и кнопку «Вступить»; повторное вступление не создаёт второго членства. Создатель может заменить приглашение, после чего прежняя ссылка перестаёт работать. Ссылка передаётся через параметр запуска Mini App; этот механизм поддерживается [Telegram](https://core.telegram.org/bots/webapps#launching-the-main-mini-app).

Обычный участник может выйти из группы. Создатель не может выйти из своей группы в первой версии; передача владения и удаление группы не входят в этот объём. Чужие личные карточки недоступны даже при прямом обращении к API.

### Редактирование и удаление

Исправление текста общей карточки видно всем участникам и сохраняет существующий прогресс. Для замены слова на другое создаётся новая карточка. При одновременном редактировании приложение обнаруживает конфликт версий и предлагает загрузить актуальный текст.

Удаление карточки исключает оба направления из последующих тренировок. На сервере используется мягкое удаление: история сохраняется, карточка не выдаётся в обычных списках. Обычный участник не удаляет общие карточки, включая свои; это право создателя группы согласно принятой модели.

## 4. Импорт списка

### Пользовательский сценарий

1. Нажать «Добавить слова».
2. Выбрать «В группу» или «Только мне». «В группу» доступно только заранее выбранному издателю, состоящему в выбранной группе; ему явно показывается её название. Остальным пользователям доступно «Только мне».
3. Вставить список в многострочное поле.
4. Нажать «Проверить список».
5. Просмотреть пары, исправить проблемные строки, исключить повторы или ненужные строки.
6. Нажать «Добавить» с числом выбранных пар. После сохранения можно сразу перейти к повторению.

### Правила разбора

- Разделение строки выполняется по первому дефису `-`, короткому тире `–` или длинному тире `—`, окружённому пробельными символами.
- Неразрывные пробелы учитываются как обычные пробелы. Краевые пробелы удаляются, пустые строки пропускаются.
- Обе стороны должны содержать текст. Слеши, запятые, скобки, внутренние дефисы и оставшиеся разделители сохраняются как часть текста.
- Строка без подходящего разделителя остаётся в предпросмотре с исходным текстом и причиной ошибки. Её можно исправить вручную либо явно исключить.
- Переводы и языковые ошибки автоматически не исправляются. Текст отображается как текст, а не HTML.
- Предел одного импорта: 500 непустых строк; длина одной стороны — до 2 000 символов. Превышение показывается до сохранения.

### Проверка на примере пользователя

| Исходная строка | Результат |
| --- | --- |
| `Purpose - цель` | Одна пара: `Purpose` и `цель` |
| `Receive - получать/принимать` | Один ответ с обоими вариантами перевода |
| `High priest - первосвященник` | Фраза остаётся целиком |
| `Cell - клетка (в теле, в тюрьме/домашняя группа (ячейка))` | Пояснения и скобки сохраняются полностью |
| `Provision - обеспечение`, повторённая дважды | Предупреждение о повторе; второй экземпляр по умолчанию исключён |
| `Выражение it depends означает "в зависимости от обстоятельств"` | Требуется ручное разделение; пример исправления: `it depends — в зависимости от обстоятельств` |

### Дубликаты и сохранение

Проверяется совпадение обеих сторон внутри вставленного списка и внутри выбранного места назначения: конкретной группы либо личного набора. Для сравнения применяются Unicode NFC, приведение регистра и схлопывание пробелов. Отображаемый текст не заменяется этим сравнительным представлением. Одинаковое слово с другим переводом не объединяется автоматически.

Повторы по умолчанию исключены; пользователь может явно включить повтор, если он нужен. Дубликаты между общим и личным набором остаются разными карточками: объединение их истории и владения в первую версию не входит.

Сохранение возможно, когда каждая выбранная строка корректна. API повторно проверяет содержимое, дубликаты и права доступа. Если после предпросмотра появились новые совпадения, он возвращает обновлённое предупреждение без частичной записи. Выбранный пакет сохраняется целиком в транзакции. Повтор того же запроса после сетевой ошибки не добавляет карточки второй раз.

## 5. Повторение

### Основной сценарий

1. На экране «Повторять» пользователь нажимает «Начать».
2. Видит только одну сторону карточки: слово/фразу либо перевод в зависимости от направления. Дополнительных подписей на карточке нет.
3. Вспоминает ответ мысленно.
4. Нажимает на карточку или кнопку «Показать ответ».
5. Видит исходную сторону и ответ одновременно. Это всё содержимое карточки; управляющие кнопки расположены отдельно.
6. Выбирает одну из четырёх оценок. После сохранения открывается следующее задание.

| Оценка | Когда выбирать | Значение планировщика |
| --- | --- | --- |
| Не вспомнил | Ответ отсутствовал или был неверным | Again |
| С трудом | Ответ верный, но потребовал большого усилия | Hard |
| Вспомнил | Ответ верный, вспомнился с обычным усилием | Good |
| Легко | Верный ответ пришёл сразу | Easy |

До раскрытия ответа оценки недоступны. Повторное нажатие на открытую карточку не выставляет оценку. Пользователь может завершить тренировку в любой момент; неоценённое задание не меняет прогресс.

### Планировщик

Используется FSRS через Python-библиотеку `fsrs`. Она поддерживает четыре оценки и вычисляет следующее повторение из истории карточки. Начальная конфигурация: стандартные параметры модели выбранной зафиксированной версии, целевое удержание `0.9`, шаги первичного обучения 1 и 10 минут, повторного заучивания — 10 минут. Это внутренняя настройка модели, а не обещание конкретной точности памяти. Персональная оптимизация коэффициентов в первой версии не требуется. Основание: [официальный репозиторий py-fsrs](https://github.com/open-spaced-repetition/py-fsrs).

Состояние ведётся отдельно для сочетания «пользователь + карточка + направление». Оценка одного участника не меняет чужое расписание. Оценка английский → русский не меняет состояние русский → английский.

Время выставления оценки необходимо для вычисления будущего повторения и хранится в UTC. Длительность просмотра карточки и длительность занятия не измеряются.

### Очередь

- Сначала выдаются наступившие короткие повторения, затем остальные задания с наступившим сроком, затем новые.
- Внутри очереди повторения сортируются по сроку; для одинакового срока используется стабильный порядок по идентификатору. Новые идут по порядку добавления.
- Оба направления участвуют в одной тренировке. Если следующей должна идти обратная сторона только что показанной пары и есть другое доступное задание той же категории очереди, выбирается оно. При отсутствии альтернативы обратное направление разрешено.
- После «Не вспомнил» карточка возвращается в короткое повторение. Когда других доступных заданий нет, разрешается показать учебное или переучиваемое задание со сроком в ближайшие 20 минут. Это позволяет продолжить без ожидания; будущие обычные повторения не подтягиваются досрочно. Подобное упреждение коротких шагов описано в [руководстве Anki](https://docs.ankiweb.net/manual/deck-options).
- Дневного лимита новых слов, нормы по времени и ограничения длины занятия нет. Пользователь заканчивает сам.
- Когда очередь доступных заданий исчерпана, показывается «На сейчас всё» и действия «К словам» и «Добавить слова».

### Надёжность ответа

Сначала сервер атомарно сохраняет оценку, журнал и новое состояние, затем интерфейс переходит дальше. Пока идёт сохранение, четыре кнопки временно недоступны. При потере связи остаётся открытая карточка с сообщением «Не удалось сохранить ответ» и кнопкой «Повторить».

Повтор запроса использует тот же ключ операции. Два одинаковых запроса дают одно событие повторения. Параллельное оценивание с двух устройств проверяет версию состояния: устаревшая попытка не применяется поверх новой. Если текст карточки изменился после её показа, устаревшая оценка не сохраняется: приложение загружает обновлённую карточку с закрытым ответом.

После закрытия и повторного открытия Mini App сохраняются все подтверждённые оценки; очередь строится по текущим данным. Точная позиция неоценённой карточки в интерфейсе не обещается.

## 6. Экраны и навигация

Основная навигация содержит три раздела: «Повторять», «Слова», «Группа». Тренировка открывается отдельным экраном без нижней навигации.

| Экран | Содержимое | Основное действие |
| --- | --- | --- |
| Повторять | Выбранная группа или личный режим; краткие количества доступных повторений и новых заданий | Начать |
| Тренировка | Большая карточка только со словом/фразой и раскрываемым переводом; четыре оценки за пределами карточки | Показать ответ → оценить |
| Слова | Поиск по обеим сторонам; фильтры «Все», «Общие», «Личные»; список пар | Добавить слова |
| Группа | Название, участники, создатель, приглашение для создателя; выход для обычного участника | Пригласить или создать группу |
| Добавление | Выбор места, поле списка, предпросмотр и исправления | Добавить выбранные пары |
| Редактирование | Два текстовых поля и доступные действия по правам | Сохранить |

Без группы раздел «Группа» предлагает создать её или воспользоваться приглашением. Если карточек ещё нет, главный экран показывает короткий текст «Добавь слова, чтобы начать» и кнопку добавления.

В словаре одна строка соответствует одной паре. Счётчики на экране повторения считают задания по направлениям; подпись «заданий» предотвращает путаницу. Общая или личная принадлежность обозначается в словаре и его фильтрах. Во время тренировки эти признаки и автор не отображаются на карточке.

## 7. Визуальная дизайн-система

### Характер интерфейса

Спокойный мобильный интерфейс с акцентом на слове, достаточными отступами и крупными зонами нажатия. Главный визуальный объект во время обучения — карточка. Интерфейс не содержит мотивационных виджетов, рейтингов и прогресса по времени.

Раскрытие ответа — простое появление текста, без обязательного 3D-переворота. Необязательная анимация занимает до 150 мс и отключается при системном предпочтении уменьшенного движения.

### Компоненты и состояния

- Учебная карточка: только вопрос и раскрываемый ответ. Сохранение оценки и ошибка сохранения показываются в области управления за пределами карточки.
- Основная и вторичная кнопки: обычное состояние, фокус, нажатие, загрузка, недоступность.
- Кнопка оценки: текст, цветовой маркер, явное состояние фокуса, блокировка повторного нажатия.
- Строка словаря: две стороны, общая/личная принадлежность, переход к деталям.
- Строка предпросмотра: корректная, дубликат, ошибка, исключённая; рядом с ошибкой всегда есть текст причины.
- Системное сообщение: ошибка связи, отсутствие доступа, недействительное приглашение, пустой набор.
- Подтверждение удаления: текст обеих сторон карточки и явное описание того, что она исчезнет из общего набора.

Для личной карточки подтверждение говорит об удалении из личного набора. Импорт сохраняет введённый текст в открытой форме при ошибке сети; ошибка не очищает поле.

Для обычного текста целевой контраст не ниже 4.5:1 по [WCAG 2.2](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html). Основной поток доступен с клавиатуры и экранного диктора. У кликабельной карточки есть доступное действие «Показать ответ»; после раскрытия ответ объявляется, фокус не теряется.

## 8. Сервер и данные

### Состав

- Backend: Python, FastAPI, SQLAlchemy и Alembic.
- Frontend: React, TypeScript и Vite; API и статические файлы доступны с одного origin.
- Данные: PostgreSQL с постоянным Docker volume.
- Повторения: библиотека `fsrs` за небольшим внутренним адаптером.
- Docker: образ приложения с собранным фронтендом и Python-сервером, отдельная база; при размещении в интернете — HTTPS reverse proxy.

Один backend содержит модули авторизации, групп, карточек/импорта и обучения. Фоновый процесс для напоминаний не нужен. Очередь повторений вычисляется по состоянию базы при обращении пользователя.

Для запуска используется бот с настроенной Main Mini App. Серверу не требуется чтение групповых чатов. Telegram-данные входа проверяются на сервере: подпись и свежесть `initData`; доверять одному `initDataUnsafe` нельзя. Бот-токен остаётся серверным секретом. Основание: [проверка данных Mini App](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app).

### Сущности

| Сущность | Содержание и инвариант |
| --- | --- |
| User | Уникальный Telegram ID, отображаемое имя |
| Group | Название, создатель |
| Membership | Пользователь и группа; уникальное членство |
| Invitation | Группа, хеш случайного токена, статус действительности |
| Card | Две стороны, автор, видимость, группа для общей либо владелец для личной, версия, признак удаления |
| StudyState | Пользователь, карточка, направление, состояние FSRS, ближайшее повторение, версия состояния; уникальность по первым трём полям |
| ReviewEvent | Пользователь, карточка, направление, оценка, момент повторения, версия содержимого и ключ операции |
| OperationReceipt | Пользователь, тип операции, ключ, хеш запроса и результат; обеспечивает идемпотентность импорта и выставления оценки |

Для общей карточки обязательна группа; для личной — владелец, а группа отсутствует. Автор и владелец не подменяются идентификаторами из клиента. Для ещё не изучавшего карточку пользователя отсутствие StudyState означает новое задание, а не отсутствие доступа к нему.

Запись результата операции создаётся в той же транзакции, что её изменения. Повтор ключа с тем же содержимым возвращает сохранённый результат, с другим содержимым — конфликт. После исправления предпросмотра новая попытка сохранения получает новый ключ. Повторная выдача результата также проверяет текущий доступ пользователя.

### Границы ответственности

Импорт возвращает разобранные пары и ошибки, но не меняет прогресс. Модуль карточек отвечает за содержимое и права. Планировщик принимает текущее состояние, оценку и время и возвращает новое состояние. Сервис обучения проверяет доступ, выбирает очередь и сохраняет результат транзакционно. Frontend не вычисляет окончательное расписание.

После изменения состава группы или удаления карточки права повторно проверяются при выдаче задания и сохранении оценки. Если доступ пропал, ответ не сохраняется, интерфейс возвращает пользователя к доступному набору с понятным сообщением.

## 10. SDD и следующий этап

Спецификация утверждена пользователем с уточнениями, внесёнными в R01, R05 и R15. Повторное утверждение прежних решений не требуется. Telegram ID единственного издателя — `1568151709`, явно сообщённый пользователем.

Следующий артефакт — отдельный план реализации через `superpowers:writing-plans`. Задачи плана связываются с ID требований и критериями приёмки. После ревью плана и выбора способа выполнения код реализуется по нему; изменения поведения сначала отражаются в спецификации и соответствующих проверках.

Проверки включают: модульные тесты разбора списка и адаптера планировщика с управляемым временем; интеграционные проверки прав, транзакций и идемпотентности; сквозные сценарии импорта, приглашения и повторения; визуальную проверку компонентов в Telegram. Тесты подтверждают прикладное поведение, а не воспроизводят формулы сторонней библиотеки.

Текущий документ не утверждает визуальный макет, не создаёт внешнего Telegram-бота и не выполняет развёртывание.
